# Фон групповых чатов

## Цель

Добавить управление общим фоном в групповые чаты и каналы сообществ. Установленный фон видят все участники диалога. Интерфейс выбора повторяет существующий выбор фона личного чата и находится во вложенном экране «Изменить чат».

## Права

- Обычный групповой чат: менять и удалять фон могут создатель и администраторы чата.
- Канал сообщества: менять и удалять фон могут участники с разрешением `manage_channels`.
- Остальные участники получают фон в данных диалога и видят его, но элементы управления не отображаются.
- Backend проверяет членство, тип диалога и соответствующее право независимо от клиентского интерфейса.

## Данные и API

Фон продолжает храниться в существующем поле `msg_dialogs.img`, чтобы не добавлять миграцию и сохранить совместимость личных диалогов. `UpdateBackground.php` принимает идентификатор диалога и URL изображения или явную команду очистки. URL валидируется по тем же правилам, что и остальные загружаемые изображения.

Endpoint сохраняет прежнее поведение для личного диалога: любой из двух участников может менять общий фон. Для группового диалога он применяет описанную выше модель прав. Ответ возвращает итоговый URL фона.

## Клиентский интерфейс

В `GroupInfoModal`, во view `edit_title`, после аватарки и названия добавляется секция «Изменить фон»:

- карточка без фона;
- карточка текущего/нового изображения;
- скрытый `input[type=file]` с `accept="image/*"`;
- индикатор загрузки;
- тот же размер, форма, preview сообщений и активная обводка, что в настройках личного чата.

После успешного запроса модалка остаётся на экране «Изменить чат», локальный диалог обновляется без перезагрузки, а родитель получает новое значение фона через `onGroupUpdated`. Ошибка показывается стандартным toast через `useNotification`.

## Поток обновления

1. Пользователь выбирает изображение.
2. Клиент загружает его существующим `uploadImage`.
3. Клиент вызывает защищённый `UpdateBackground.php`.
4. Backend проверяет права и обновляет `msg_dialogs.img`.
5. Клиент обновляет выбранный диалог и список диалогов.

Удаление использует тот же endpoint с пустым итоговым фоном, без загрузки файла.

## Тестирование

- Backend: личный участник, creator/admin обычной группы и `manage_channels` сообщества получают доступ; обычный участник и роль без разрешения получают 403.
- Клиент: секция присутствует только при `canManageChannel`, вызывает upload/update/clear и передаёт новый фон родителю.
- Регрессия: личные фоны продолжают обновляться, групповой фон отображается в основном контейнере сообщений.
- Общие проверки: PHP lint, TypeScript, существующие тесты и production build.

## Вне scope

- Персональные фоны, отличающиеся у каждого участника.
- Галерея встроенных обоев.
- Отдельное разрешение роли только для фона.
- Новая таблица или SQL-миграция.
