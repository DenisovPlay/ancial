# Консолидация Pulse API на backend.ru.zypo.cc

## Цель

Перенести файлы и обязанности поддоменов `pulse.ancial.ru` и
`pulse-lyrics.ancial.ru` на `https://backend.ru.zypo.cc`, убрать из клиента и
PHP-бэкенда зависимости от старого бренда Ancial и сохранить работоспособность
локального и S3-аудио.

Слой обратной совместимости не создаётся: старые поддомены не проксируются и не
получают redirect. После деплоя единственным хостом этих API и файлов становится
`backend.ru.zypo.cc`.

## Конечная структура

- `php-v2-api/backend.ru.zypo/music/` содержит все локальные MP3 из
  `php-v2-api/pulse.ancial/music/`.
- `php-v2-api/backend.ru.zypo/track.php` публично отдаёт S3-аудио с поддержкой
  HTTP Range и дисковым кэшем.
- `php-v2-api/backend.ru.zypo/modules/aws/` содержит существующий AWS SDK.
- `php-v2-api/backend.ru.zypo/modules/pulse/` содержит конфигурацию хранилища,
  S3-клиент, загрузку/удаление объектов, валидацию аудио и нормализацию публичных
  URL.
- `php-v2-api/backend.ru.zypo/api/V2/UniLyrics.php` содержит актуальный lyrics
  endpoint.
- `php-v2-api/backend.ru.zypo/api/V2/ytm.php` переносится вместе с lyrics
  сервисом, но не участвует в основном клиентском запросе UniLyrics.
- Каталоги `php-v2-api/pulse.ancial/` и
  `php-v2-api/pulse-lyrics.ancial/` удаляются после переноса всех нужных файлов.

## Публичные URL

Локальное аудио:

```text
https://pulse.ancial.ru/music/<file>
→ https://backend.ru.zypo.cc/music/<file>
```

S3-аудио:

```text
https://anci.hb.ru-msk.vkcs.cloud/music/<file>
→ https://backend.ru.zypo.cc/track.php?track=<encoded-file>

https://anci.hb.bizmrg.com/music/<file>
→ https://backend.ru.zypo.cc/track.php?track=<encoded-file>
```

Сохранённые ранее proxy-ссылки также переводятся:

```text
https://pulse.ancial.ru/track/<file>
→ https://backend.ru.zypo.cc/track.php?track=<encoded-file>
```

Lyrics:

```text
https://lyrics.pulse.zypo.cc/UniLyrics.php
→ https://backend.ru.zypo.cc/api/V2/UniLyrics.php
```

Параметры и текстовый LRC-ответ `UniLyrics.php` сохраняются, поэтому клиент
продолжает передавать `a`, `t`, `d` и `type=alternative`.

## Нормализация track src

В `modules/pulse` создаётся одна функция преобразования `src`. Её используют все
актуальные V2-обработчики, которые возвращают или изменяют треки:

- `api/V2/pulse/GetArtist.php`;
- `api/V2/pulse/GetPlaylist.php`;
- `api/V2/pulse/GetTrack.php`;
- `api/V2/pulse/Library.php`;
- `api/V2/pulse/Management.php`;
- `api/V2/pulse/Search.php`;
- `api/V2/admin/Music.php`, если ответ содержит `src`.

Преобразование выполняется через разбор URL, а не через разрозненные
`str_replace`. Имя файла декодируется, проверяется и затем кодируется через
`rawurlencode`. Функция:

- сохраняет уже корректные URL `backend.ru.zypo.cc`;
- переводит локальный legacy-host в `/music/`;
- переводит известные S3-host в `/track.php?track=`;
- переводит старый `/track/<file>` в новый query endpoint;
- не переписывает неизвестные внешние источники;
- отклоняет traversal, управляющие символы, вложенные пути и неподдерживаемые
  расширения.

База данных не требует массовой миграции: legacy `src` нормализуются на границе
API. Новые загрузки записывают канонический исходный S3 URL, а наружу всегда
возвращается URL нового backend.

## S3-модуль

Существующие значения endpoint, region, bucket, access key и secret key
сохраняются без изменения и переносятся в конфигурацию внутри
`modules/pulse`. Публичные обработчики больше не содержат копий ключей.

Модуль предоставляет операции:

- создание настроенного `S3Client`;
- проверка загруженного аудиофайла;
- загрузка объекта только в префикс `music/`;
- безопасное извлечение object key из сохранённого `src`;
- удаление объекта только из префикса `music/`;
- формирование канонического S3 URL и публичного backend URL.

Загрузка разрешает форматы, которые способен отдавать player endpoint: MP3,
WAV, OGG и M4A. Проверяются:

- наличие поля и код `UPLOAD_ERR_OK`;
- `is_uploaded_file`;
- максимальный размер, совместимый с текущим лимитом 10 388 608 байт;
- расширение;
- MIME через `finfo`;
- непустой временный файл.

Пользовательское имя не используется как object key. Сервер создаёт
непредсказуемое имя из криптографически случайного значения и проверенного
расширения.

Удаление не принимает URL или key напрямую от HTTP-клиента. V2 endpoint сначала
проверяет авторизацию, владельца трека или роль администратора, получает `src` из
БД и только затем передаёт его внутреннему модулю.

## Изменения API

`api/V2/pulse/Management.php` загружает файл непосредственно через S3-модуль
вместо cURL-запроса к `pulse.ancial.ru`. Существующий JSON-контракт
`success/data/error` сохраняется.

`api/V2/Media.php` использует тот же внутренний upload-модуль после проверки
авторизации. Он больше не выполняет proxy upload на старый хост.

`api/V2/pulse/Management.php` и `api/V2/admin/Music.php` удаляют S3-объекты
внутренним вызовом. Старый публичный файл `s3delHIDDENsecret.php` не переносится
как endpoint.

Legacy `api/pulse` перестаёт ссылаться на старые поддомены. Поскольку V2 является
актуальным API, новые storage-возможности добавляются только в V2; старые
обработчики либо используют общий модуль там, где остаются в репозитории, либо
не содержат Ancial URL.

## Потоковое аудио

`track.php` принимает только `GET` и `HEAD` с параметром `track`. Допустимое имя
представляет собой один basename с расширением MP3, WAV, OGG или M4A.

Endpoint:

- строит upstream URL только из фиксированного S3 base URL и проверенного имени;
- не принимает произвольный URL;
- запрещает traversal и вложенные пути;
- использует TLS verification;
- не следует произвольным redirect;
- ограничивает connect и общий timeout;
- скачивает во временный файл и выполняет атомарный rename;
- использует lock для конкурентной загрузки одного файла;
- удаляет повреждённые и пустые временные файлы;
- поддерживает `Range`, `If-None-Match`, `HEAD`, `Content-Length`,
  `Content-Range`, `Accept-Ranges` и `416`;
- выставляет `X-Content-Type-Options: nosniff`;
- сохраняет текущие лимит кэша 2 ГБ и TTL 7 дней;
- хранит runtime-кэш вне переносимой папки `music`, чтобы очистка кэша не
  затронула локальные MP3.

Абсолютный путь к кэшу вычисляется относительно document root или берётся из
конфигурации; путь `/www/wwwroot/pulse.ancial.ru/` удаляется.

## Lyrics

`UniLyrics.php` переносится в `/api/V2` с прежним поиском Musixmatch и fallback
на LRCLIB. CORS остаётся совместимым с веб-клиентом. Ошибки внешних сервисов
логируются без токенов и внутренних путей.

Memcached остаётся необязательной runtime-зависимостью: если расширение или
локальный сервер недоступны, endpoint продолжает работать без кэша, а не падает
до обращения к lyrics provider.

`ytm.php` переносится без тестовых значений по умолчанию, `var_dump` и выдачи
отладочных upstream-ответов. Он валидирует обязательные `artist` и `title`,
возвращает JSON и корректный HTTP-код ошибки.

## Клиент

`app/config.ts` остаётся единственным местом определения доменов. Значение
`PULSE_LYRICS_BASE` меняется на:

```text
https://backend.ru.zypo.cc/api/V2
```

`app/pulse/player/lyrics-service.ts` продолжает строить URL
`${PULSE_LYRICS_BASE}/UniLyrics.php` и не содержит старых доменов.

По всему клиенту и PHP-бэкенду выполняется проверка на оставшиеся ссылки
`pulse.ancial`, `pulse-lyrics.ancial`, `lyrics.pulse.zypo.cc` и S3 host,
использованные вне централизованной конфигурации/normalizer.

## Ошибки и безопасность

- Ошибки upload/delete не возвращают текст исключений AWS SDK клиенту.
- HTTP-статусы различают неверный запрос, отсутствие авторизации, запрет,
  отсутствие объекта, слишком большой файл и внутреннюю ошибку.
- Ответы V2 сохраняют формат `success`, `data`, `error`.
- Доступ к upload требует сессии; пользовательские delete требует владения
  треком; административный delete требует role `3`.
- Публичного анонимного upload/delete endpoint не остаётся.
- Ключи сохраняются по прямому требованию и не меняются в рамках этой задачи.

## Проверка

Автономные PHP-тесты без подключения к рабочей БД или S3 покрывают:

- каждое правило legacy URL → новый URL;
- пробелы и Unicode в имени;
- сохранение уже канонического URL;
- неизвестный внешний URL;
- traversal и вложенные пути;
- допустимые и недопустимые object key;
- расширение, MIME и лимит размера upload;
- разбор одиночных, открытых и недопустимых HTTP Range.

После реализации выполняются:

- RED/GREEN циклы для новых helper-функций;
- `php -l` для каждого PHP-файла в `php-v2-api/backend.ru.zypo`;
- PHP-тесты;
- штатные проверки TypeScript/React проекта;
- поиск всех старых Ancial/Pulse доменов;
- проверка наличия всех 24 перенесённых MP3;
- проверка отсутствия старых каталогов после переноса.

Реальные операции S3, БД и Memcached не выполняются локально без соответствующей
инфраструктуры; их интеграционные точки проверяются через чистые функции,
синтаксис и существующие контракты.
