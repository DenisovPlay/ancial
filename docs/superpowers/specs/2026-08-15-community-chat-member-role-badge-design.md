# Роль участника сообщества в информации о канале

## Цель

В списке участников группового чата, привязанного к сообществу, показывать одну наиболее высокую значимую роль пользователя с цветом этой роли.

## Поведение

- Функция применяется только к чатам, у которых задан `community_id`.
- Владелец сообщества получает бейдж «Владелец» и имеет максимальный приоритет.
- Для остальных пользователей выбирается назначенная роль с наименьшим `position` (самая высокая в иерархии), затем по `id` для стабильного результата.
- Системная базовая роль `member` не показывается.
- Системные роли локализуются на клиенте по `system_key`; имя кастомной роли отображается как сохранено в сообществе.
- Цвет кастомной или системной роли берётся из `community_roles.color`. Цвет владельца остаётся фирменным фиолетовым.
- Обычная роль внутри самого группового чата (`owner`/`admin`/`member`) продолжает управлять доступом и действиями, но не используется как роль сообщества.
- В непривязанных групповых чатах текущий интерфейс не меняется.

## Архитектура

`GetDialog.php` уже формирует список активных участников и проверяет доступ к каналу. Для привязанного сообщества он одним дополнительным запросом получает роли только этих участников, выбирает высшую значимую роль и добавляет к каждому элементу `members` необязательное поле `community_role`.

Формат поля:

```json
{
  "id": 12,
  "name": "Редактор",
  "color": "#a855f7",
  "position": 20,
  "system_key": "editor",
  "is_owner": false
}
```

Для владельца `id` равен `null`, `system_key` равен `owner`, а `is_owner` — `true`.

Клиент не выполняет отдельный запрос списка участников или ролей: это исключает лишний waterfall, мерцание и необходимость выдавать право `manage_members`.

## Безопасность и совместимость

- API раскрывает только публичные отображаемые свойства одной роли и только для участников уже доступного пользователю канала.
- Старые клиенты проигнорируют новое необязательное поле.
- При отсутствии таблиц/назначений или значимой роли участник отображается без бейджа.

## Проверка

- Контрактный тест серверного файла подтверждает выбор владельца, сортировку ролей и исключение `member`.
- Контрактный тест компонента подтверждает один бейдж и локализацию системных ролей.
- PHP syntax check, ESLint целевого компонента и TypeScript проверяют интеграцию.
